# Coupon Campaign Revenue Prediction

A machine learning project that predicts the **revenue generated by a promotional coupon campaign** from its configuration and the branch's history. Built as an individual, end to end ML project, from messy raw data to a validated model.

## Problem Statement

Businesses run many coupon campaigns with different reward structures, budgets, and target branches, but it is hard to know in advance which campaign setup will actually drive revenue. This project builds a model that predicts campaign revenue from its configuration and historical branch behavior, to support better campaign planning.

## Objective

Train and compare regression models to predict `CAMPAIGN_REVENUE_SAR` for a coupon campaign, and identify which features drive revenue the most.

## Project Workflow

1. **EDA:** inspected 20,400 campaigns × 17 columns; checked structure, missing values, and duplicates (400 duplicate rows).
2. **Data Cleaning**
   - **Dates in four formats** (`2025-11-25`, `2025-12-08 00:00:00`, `Jan 31, 2026`, `17/12/2025`). Checking the slash format showed it is **day/month/year**, so it is parsed explicitly instead of letting pandas guess. This corrected the dates of **3,533 campaigns** and kept **1,224 valid campaigns** that automatic parsing would have discarded as ending before they start.
   - Removed currency text and thousands separators from numeric columns (for example `739 SAR`, `2,410`).
   - Unified inconsistent category labels (`percent`, `PERCENT`, `Percentage` → `percentage`).
   - Removed impossible values: negative revenue, a `99999999` placeholder, negative reward amounts, and campaigns ending before they start.
   - Removed duplicates, leaving 19,093 campaigns. Missing values are filled after the train/test split, using the training data only, to avoid data leakage.
   - Kept revenue outliers (about 5.5% by the IQR rule), since they likely represent genuinely high performing campaigns.
3. **Feature Engineering:** campaign duration, start month, an uncapped usage flag, and budget per usage.
4. **Modeling:** naive baseline (always predicts the mean), Linear Regression, Random Forest, and XGBoost.
5. **Hyperparameter Tuning:** `RandomizedSearchCV` for Random Forest and XGBoost, with the final model chosen by cross validation rather than by the test set.
6. **Evaluation and Diagnostics:** MAE, RMSE, and R², a train vs test comparison to check for overfitting, a time based split to check performance on future campaigns, actual vs predicted and residual plots, and permutation feature importance.

## Results

| Model | MAE (SAR) | RMSE (SAR) | R² |
|---|---|---|---|
| Naive Baseline | 23,304 | 33,093 | 0.000 |
| Linear Regression | 12,198 | 18,448 | 0.689 |
| Random Forest (Tuned) | 6,390 | 10,815 | 0.893 |
| **XGBoost (final)** | **4,002** | **6,917** | **0.956** |
| XGBoost (after search) | 4,144 | 7,126 | 0.954 |

**XGBoost** explains **95.6%** of the variance in campaign revenue, with an average error 83% lower than the naive baseline. The hyperparameter search did not beat the initial XGBoost settings in cross validation (MAE 4,462 vs 4,336 SAR), so the initial model was kept.

**Overfitting check:**

| Model | Train R² | Test R² |
|---|---|---|
| Linear Regression | 0.679 | 0.689 |
| Random Forest (Tuned) | 0.984 | 0.893 |
| **XGBoost (final)** | **0.990** | **0.956** |

Linear Regression underfits, Random Forest overfits noticeably, and XGBoost keeps a high test score, so it generalizes well.

**Performance on future campaigns:** trained only on the earliest 80% of campaigns by start date and tested on the latest 20%, XGBoost reaches **R² = 0.955** (MAE 4,027 SAR), almost the same as with the random split. The model can therefore be relied on to predict upcoming campaigns.

**What drives revenue (permutation importance):**

| Feature | Increase in test MAE when shuffled (SAR) |
|---|---|
| Campaign duration | 10,871 |
| Branch average order value, last 90 days | 9,431 |
| Minimum order threshold | 8,237 |
| Branch orders before the campaign | 7,479 |
| Reward percentage | 6,010 |

Revenue depends on both how a campaign is designed (duration, minimum order, reward percentage) and on the branch's history (average order value, prior orders). Budget, usage caps, and start month add almost nothing once these are known.

## Limitations & Future Work

- Prediction error grows with predicted revenue, and the largest campaigns tend to be under predicted. Training on the logarithm of revenue could stabilize this.
- The data covers about one year of campaigns, so seasonal effects cannot be fully captured.
- External factors such as holidays, competitor campaigns, and marketing spend are not included.
